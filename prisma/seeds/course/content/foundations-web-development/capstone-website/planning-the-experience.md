## Planning the Experience

A strong website starts before code. Planning defines who the site serves, what they need, what content supports that goal, and which implementation slice should be built first.

### Start with the outcome

Write a narrow problem statement. A vague goal such as "make a portfolio" invites random sections. A specific goal such as "help a hiring manager understand three frontend projects and contact me" gives design and content a clear direction.

- Audience: who is the site for?
- Goal: what should they understand or do?
- Evidence: what content builds trust?
- Primary action: what should happen next?

### Organize the content

Inventory the content before choosing a visual layout. Group related information and order it from essential to supporting. Missing content is easier to find in an outline than in a finished design.

```text
Home
- Short promise
- Featured work
- Skills evidence
- Contact action

Project detail
- Problem
- Role
- Process
- Result
```

### Sketch responsive structure

Low-fidelity sketches help you reason about hierarchy without getting stuck on decoration. Sketch mobile first, then consider how additional space can improve scanning on larger screens.

### Plan vertical slices

Build one complete path before building every section. A thin slice might include real navigation, one responsive page, accessible buttons, and deployed assets. This creates something testable early.

> A slice is valuable when it connects content, design, implementation, and review.

### Planning checklist

- [ ] The audience is specific.
- [ ] The primary action is visible.
- [ ] Content supports the action.
- [ ] Mobile and desktop hierarchy are sketched.
- [ ] The first build slice is small and complete.

### Guided practice

Write a one-paragraph brief for your capstone site. Create a content outline and sketch one mobile layout plus one desktop layout. Mark the primary action and the evidence users need before taking it.

### Key takeaway

Planning aligns audience, content, design, and implementation around one clear experience before details multiply.
